# Useful program result: integer readings cleaner

On 2026-11-01 the learner selected `positive → unique → ascending` from
three input/output examples. The emitted standalone Python program reads a
JSON file of integer readings, removes nonpositive readings and duplicates,
sorts the result and writes a new JSON file. It uses the Python standard
library and does not depend on this repository or a neural runtime.

The same selected composition emits a CURLEE routine with loops, branches
and fixed arrays. Its interface accepts up to 256 signed integer readings
and writes the resulting array and length. JSON parsing and file handling
are implemented only in the Python output.

## Actual execution

| Check | Result |

| CURLEE compiler check and VM execution, same new arrays | 100/100 correct |

The evaluation inputs were generated after training and synthesis ended.
They include empty input, all-nonpositive input, duplicates, 201 descending
integers and 95 seeded random arrays of up to 100 integers. Expected answers
come from an independent set/filter/sort oracle. No held result was used to
repair or retry the learned composition.

The Python executions used separate filesystem and network namespaces,
read-only source/input mounts, a temporary output directory and CPU, memory,
file-size and wall-time limits. The actual input-overwrite rejection also
has a regression test.

CURLEE execution used its existing resource guard, fuel-limited VM and
unchanged compiler binary, SHA-256
`412d0e6ee5b8fb9e380322683863849523e1a5797e7e7dbd42bf174b138555ac`.
This identifies the executed binary; it does not establish a source-matched
or generally qualified compiler. The 100 cases ran as individual harnesses,
with both `check` and `run` required. Their recorded compiler/VM time totals
15.052 seconds, excluding guard and wrapper overhead.

Earlier combined 100-case and five-case harnesses were stopped by the
resource guard with status 75. Its message did not identify which budget
condition fired. These partial attempts are retained; no resource limit was
raised. Earlier emitter failures involving unsupported `Vec` annotations,
Boolean equality, reference passing and loop-bound contracts are also
retained. The fixes changed the generic emitter and harness, not the learned
composition or CURLEE compiler.

## What the learner contributed

The policy chooses and orders operations from a supplied library of 13
integer-list operations, then explicitly stops. Search retains up to 32
states, explores the top four neural choices at each step and allows at most
three operations. It receives concrete examples; natural-language requests
are not an implemented input interface.

Training used 649 other teacher compositions and 14,850 teacher states,
generated by the task engine without an LLM teacher. The complete target
behavior, including known aliases, was excluded by equivalence on 24 probe
arrays. This finite probe check is not a proof of functional separation on
every possible array. Forty epochs and the initial untrained check took
4.910 seconds in the recorded run; this is one seed and one task.

The emitter supplies operation implementations, variable naming, loops,
branches, bounds contracts and command-line/file handling. The policy did
not invent sorting or JSON parsing. The result demonstrates a useful
library-composition synthesizer. It does not demonstrate a general Python
or CURLEE programmer, arbitrary control-flow construction, unfamiliar
library use, code repair or recursive self-improvement.

This is enough evidence to continue bounded useful-program experiments.
The next capability check should use several unseen useful tasks and report
every attempt, followed by a task requiring a control-flow decision the
learner actually constructs. More model-family comparisons do not answer
that question.

## Run and reproduce

The generated [Python utility](
../../artifacts/useful-program-v1-20261101/python/clean_readings.py) accepts
input and output filenames:

```sh
python3 artifacts/useful-program-v1-20261101/python/clean_readings.py \
  readings.json cleaned.json
```

For input `[7,-2,7,0,4,1,-9,4]`, it writes `[1,4,7]`.
The [CURLEE routine](
../../artifacts/useful-program-v1-20261101/curlee/clean_readings.curlee),
[Python execution report](
../../artifacts/useful-program-v1-20261101/report.json) and
[CURLEE execution report](
../../artifacts/useful-program-v1-20261101/curlee-execution.json)
preserve the selected program, inputs, expected/actual outputs and compiler
results. Each CURLEE batch has its own source hash.

To reproduce with a fresh output directory:

```sh
flock -n /tmp/rsi-programmer-builder.lock \
  env OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 .venv/bin/python \
  -m scripts.measure_useful_program --output /tmp/useful-program-new

python3 /home/joe/Projects/curlee/scripts/run_limited.py \
  /usr/bin/python3 -m scripts.check_useful_curlee \
```

The CURLEE checkout is local-only and is not included in this repository.
Run the commands sequentially; status 75 means the guard stopped or refused
work. A partial command is not a pass.
