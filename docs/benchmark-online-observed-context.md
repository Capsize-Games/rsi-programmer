# Observed-context online graph diagnostic

The counterbalanced baseline independently replayed all 8,640 episodes and
rejected seven corruption controls. Its exploratory follow-up trigger passes;
the stronger all-orders underperformance label is false. This protocol is
frozen before measuring the observed-context intervention.

## Question and scope

This separate experiment tests whether giving the controller the current
task's six observed examples before its first lane choice helps it select a
root-operator lane, and whether online learning uses that context. The examples
are task specifications and include observed target outputs. They are not
hidden root, phase, task-ID, answer-key, or held labels. This changes the
policy's information set compared with the original feedback-only baseline.
A gain cannot be attributed to feedback-only learning or described as an
SNN-learning-only improvement.

Candidate feedback remains post-execution: the environment executes each
chosen graph on the six observed rows, then returns the existing reward. Decision features exclude solver results, root or phase metadata, task
identifiers, the exact answer polynomial and the 32 held input-output pairs.
An opaque episode ID is used only for boundary validation; it never enters
encoding, action probabilities or updates. Held checking remains
outside the policy.

## Context encoding and state

For each episode, flatten the six observed integer `(x, y, target)` triples
in source-corpus order to 18 scalars and normalize each `v` as
`v / (1 + abs(v))`. Do not sort or use hashes/opaque identifiers as choice
features. The
frozen fixture includes a row-major 18-by-16 projection matrix per model
seed. Each matrix is generated by `random.Random()` seeded with version 2
from `online-observation-context-v1:{seed}`, drawing row-major entries from
`(-1, 0, 1)`. This projection is shared by all four context-conditioned
neural arms at that seed and does not consume randomness from the original
encoder or policy-choice RNG.

For hidden unit `k`, compute once per episode:

```
context_current[k] = sum(C[j][k] * h[j] for j in range(18)) / 18
```

Add the task-constant current to the original six-feature encoder current at
each of the existing six LIF steps. Use the same projection and membrane
addition in the binary-LIF and continuous-leaky arms. Keep the original
six-column encoder bytes, hidden count, steps, readout dimensions, action
sampler, reward, baseline, learning rate, update rule, clipping, and
current-decision credit unchanged. Do not train the projection or add an EMA.

At episode boundaries, membrane and pending credit clear. In the persistent
SNN and online nonspiking arms, the readout and reward baseline persist
within an order and budget. Frozen and reset controls retain
their respective behavior. Boundary snapshots
record the context-encoding version, projection seed and hash, base weights,
baseline, and policy RNG state. The context projection must not advance or
replace the policy sampling RNG.

Before the main matrix, measure encoder context capacity at the cold initial
feature vector `(1, 0, 0, 0, 1, 0)`: count distinct 16-value hidden-rate
vectors over all 48 contexts for each seed and for binary-LIF and
continuous-leaky modes. For this count, round rates to 12 decimal places.
This is a predeclared diagnostic only. Record it before the benchmark and do
not retune, exclude a seed, or change the encoding based on the result.

## Comparisons and gates

The original no-context experiment remains a separately frozen reference; do
not merge its rows into this run. Compare context-conditioned `persistent_snn`
with context-conditioned `frozen_snn` and `episode_reset_snn` to test whether
persistent updates help when the observed examples are available. Compare it
with context-conditioned `online_nonspiking` for the SNN-specific question.
The same-run `grammar_streaming` arm provides the deployment comparison for
both budgets and all six orders.

At budget 144, the adaptation gate must pass separately in every phase order:
`persistent_snn` must exceed both frozen and episode-reset SNN in first-lane
accuracy by at least 10 percentage points pooled over the 144 task-seed rows
in that order, have a positive first-lane margin for each seed, and accept at
least as many tasks as each comparator. The SNN-specific gate also applies in
every order: persistent SNN must exceed online nonspiking first-lane accuracy
by at least 10 points pooled, accept at least as many tasks, and use no more
total CPU; no per-seed first-lane margin is required for this gate. At both
budgets and in every order, `persistent_snn` must accept at least as many
tasks as `grammar_streaming` and use no more total CPU. Report every order's
gate result; no pooled pass can hide a failed order.

Report the original no-context persistent arm beside the context-persistent
arm descriptively, with its separate-bundle provenance. Do not claim the
comparison isolates a causal SNN effect; the context arm receives more
current-task information. Keep root-family and phase-position analyses
separate. Pair by task content, not by common random draw; record
`rng_draw_offset_before` and `rng_draw_offset_after` on each episode row.

## Measurements and limits

Record context construction CPU per episode, cold policy probe CPU, capacity
diagnostic CPU, policy and update work, first lane, acceptance, candidate
count, failures/censoring, source and model-state hashes, context and
projection hashes, and full CPU cost. Include context preparation and cold
probe in the full-cost comparison. Report capacity diagnostic overhead
separately and include it in total experiment CPU. The capacity side study
never affects a policy or selects an encoding, so it is excluded from per-arm
search gates; no allocation of its cost to individual arms is claimed. Include setup/reset, graph
execution, updates, and held-checker CPU. Keep all failures in summaries and
denominators. A sequential process may report whole-process peak RSS only;
it cannot support per-arm peak-memory claims.

This is a software diagnostic on one small synthetic task stream. Repeated
functions do not establish generalization to new functions. It does not
validate real sensors, Raspberry Pi deployment, chip behavior, or energy use.
Any hardware-learning claim needs a separate sensing, update, persistence,
power, and evaluation contract.
